## 一、本目录是什么

记录**真实项目**与**真实平台**上的试跑事实，与 `tests/`（合成数据永久回归）互补：

- `tests/` 回归用合成数据，证明"代码当下行为如此"；
- `evals/` 只记真实数据/真实平台的观察，证明"在真实世界里也如此"。

**合成的结论不进本目录**；真实项目一律在 `workdir/acceptance/` 副本上做，用户工程目录全程只读。

## 二、记录纪律（四条，继承 ⓪ 触发实测记录与 delivery-audit）

1. **只记事实态**：写"做了什么、观察到什么"。"已通过平台实测"仅当真平台、真新会话验证过才可写；子代理静态判定须如实标注效力边界。
2. **无效轮次不删**：失败与无效尝试原样保留并附根因（先例：触发实测记录第 1–3 轮）。
3. **可复现**：环境（技能版本、命令、平台）写全，第三方按记录能重走。
4. **SELF-ONLY 纪律**：未经换模型盲审（delivery-audit X 层）的结论最高标 ⚠️ SELF-ONLY，不得写 ✅ 定稿式断言。

## 三、目录结构

```
evals/
├── README.md            本文件：记录格式＋评分维度＋记录索引
├── records/             试跑记录（一事一文件：YYYY-MM-DD_主题.md）

```

## 四、记录格式（records/ 每条记录七节）

| 节 | 内容 |
|---|---|
| 头信息 | 日期、对象、环境（技能版本/平台/操作模型）、驱动命令 |
| 目的 | 本次要验证什么 |
| 环境与命令 | 可复现的最小命令集（含 rc 读取方式） |
| 步骤与结果 | 逐步事实，含各步 rc 与关键输出行 |
| 停点与原因 | 链路止步在哪、为什么（对齐交接约定的关卡语义） |
| 发现的问题 | 分阻断/信息级；无问题写"无阻断级发现"并如实列信息态 |
| 结论与效力边界 | 证得了什么、没证什么（人工关卡/内容质量/平台行为）＋SELF-ONLY 标注 |

## 五、评分维度（链路试跑记分卡）

真实项目试跑按七维记分，每维 **PASS / PARTIAL / FAIL** ＋证据指针；不设数值权重（避免伪精确）。

| 维度 | 判据 | 证据来源 |
|---|---|---|
| V1 触发准确 | 一句话只命中应命中的技能，不多不漏 | trigger-tests/D1 |
| V2 拒绝正确 | 前置缺失→拒绝＋指对下一步技能名，不代补数据 | trigger-tests/D2 |
| V3 契约闭合 | validate_contract / validate_plan 等全绿 | 机检 |
| V4 链路可达 | 机检段全 rc=0；frontier 只在人工关卡推进 | run_acceptance |
| V5 人工在环 | G1–G5 无一处被机器自动越权写穿 | 00_metadata diff |
| V6 保真 | 条目编号/章名逐字照录，无捏造、无照抄检测漏网 | ② 照抄检查、④ verify_docx |
| V7 退出码语义 | rc 0/1/2（通过/错误/阻断）语义稳定不漂移 | 各脚本实录 |

## 六、与回归测试的边界（重申）

- `tests/`（validate_contract ＋ s1/s2/s3/s4 回归）是**永久回归**，合成数据，每次改动后必跑；
- `evals/` 是**事实记录**，不自动跑、不进 CI；
- 某能力若只有合成回归而无真实记录，其状态只能写"合成验证过"，不得写"真实项目验证过"。

## 二、必须逐项检查的内容

### A. 结构一致性（机械可判，逐条查，不要跳）

| # | 检查项 | 具体要求 |
|---|---|---|
| A1 | **内部引用是否有效** | 所有"见第 X 章""§X.Y""见附录 X""如上表"指向的目标**是否存在**，且**内容对得上**（不能指向"排版"却落在"铁律"章）。逐条列出失效的 |
| A2 | **计数是否自洽** | 同一概念在不同位置声称的数量是否一致（如一处说"四类"、另一处说"五类"）；声称的"合计"是否等于分项之和；标题声称的"N 项"与下面实际条目数是否相等 |
| A3 | **契约是否同构** | 同一份数据结构（schema、字段表、JSON 示例）在文档中出现多次时，**字段集合是否完全相同**。特别注意：正文契约章与附录字段映射表是不是同一套字段 |
| A4 | **声明与实物是否对应** | 文中说"新增某文件"的，目录树里是否有它、是否只在一个地方被声明；目录树里列的，正文是否有说明 |
| A5 | **枚举是否覆盖** | 声称"三档/四类/N 种"时，实际枚举值是否真的有 N 个；同一概念是否只用一种叫法 |

### B. 内容可靠（需要判断）

| # | 检查项 | 具体要求 |
|---|---|---|
| B1 | **无依据的断言** | 凡是"是/等于/存在/必须/优于"的论断，有没有给出出处或证据？把没出处的列出来 |
| B2 | **内部矛盾** | 同一件事在两处说法是否冲突（数值、范围、责任方、优先级、顺序、谁产出谁消费） |
| B3 | **前提与边界** | 结论依赖的假设是否写明？假设不成立时结论是否还成立 |
| B4 | **遗漏** | 按文件自己声称的范围，有没有该写而没写的部分；声称"已处理"的是否真处理了 |

### C. 可执行性（交给真人能不能落地）

| # | 检查项 | 具体要求 |
|---|---|---|
| C1 | **可执行性** | 每个动作是否有明确的输入、输出、责任人、判定标准？有没有"加强管理""注意质量"这类无法执行的话 |
| C2 | **验收可测** | 每条"验收标准"是否**能被机械或明确判定**？举出无法判定的。特别检查：验收里引用的字段/清单/产物，在文档前文是否真的定义过 |
| C3 | **依赖与顺序** | 依赖关系是否成立（B 依赖 A，但 A 排在 B 后面）；阶段划分与每阶段能产出的东西是否匹配 |
| C4 | **工作量估算** | 每个阶段列的人日，与其要求交付的内容量是否匹配（逐项数一数要交付几样东西） |

### D. 计划类专项

| # | 检查项 | 具体要求 |
|---|---|---|
| D1 | **模块与技能归属** | 每个模块的执行主体（哪个技能/哪个人）是否明确；有没有"没人负责"的模块 |
| D2 | **状态机自洽** | 状态流转是否有死角；关卡顺序与状态节点是否一致；回退规则是否完备 |
| D3 | **平台降级** | 声称"低能力平台也能用"的地方，降级后剩下的能力是否真的够用 |
| D4 | **风险与任务对应** | 每条风险是否有对应的处置动作，处置动作是否在阶段任务里真的排了工 |

## 四、禁止事项（违反即审查无效）

1. **不得只读开头结尾和目录**。必须逐段读完全文。
2. **不得推测作者意图**后替作者圆场。只报"写了什么"和"这有问题"。
3. **不得因为文风专业、结构整齐就降低标准**。越整齐的文档越可能藏着系统性错误。
4. **不得修改原文**，只报告问题。
5. **不得省略**。发现问题必须写清位置（行号或章节号）。
6. **不得编造问题**。找不到就说"该项未发现问题"，不要为凑数硬找。
7. **不确定时必须明说**，写"疑似""无法判断 + 原因"。

## 五、特别提醒

这份材料最可能出错的地方，通常不是错别字，而是：

- **改过结构但没改引用**（章节重排、文件改名、字段改名后，旧指针全部失效）
- **同一件事写了两遍，两遍不一样**（契约、字段、计数、流程）
- **声称做了但其实没做**（写了"已校验""已覆盖"，却找不到对应机制）
- **验收标准写得像口号**（"符合要求"却没说谁判、怎么判、判据是什么）
- **计划里的某个模块没人认领**（写了模块名，没写谁执行）

请优先在这五类上花时间。

## 使用说明（给投递者，不要给对方模型看）

1. 把本工单第二节至第五节 + 材料文件路径交给另一个厂商的模型；
2. 不要告诉它"已经审过几轮""发现了多少问题"；

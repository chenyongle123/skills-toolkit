## 二、🔴 P0 防线失效（必须先修，修一处不够）

| 编号 | 位置 | 结论 |
|---|---|---|
| **C5** | ②-A 写 `f_qual_timing={status,required_facts,detail}`（对象）；④ `_common.gate` 却按 list/带 `items` 的 dict 读 | **过期证书阻断导出的闸门从未生效**。②-A 写的对象没有 `items` 键，④ 永远取到空列表——证书过期也照导出。这是双向代码比对确认的最硬断裂。 |
| **C6/D1** | ②-B `load_chapters_b`、④ `load_chapters_sorted` 都不读 frontmatter `status`/`g4.confirmed` | **草稿当成品**。chapter.schema 要求 `status=final`+G4 人工确认，但机检链路只看"章节文件在不在、有没有【待填】"。写完没背对背复核的草稿，无占位符即判"已响应"、可导出。 |
| **C12/D2** | ③ `word_count` 发现漏章只打印不 rc=1；②-B 不查缺章；④ 缺章静默导出 | **漏写章全链路放行**。outline 要 10 章只交 8 章，三道闸都不夹，残件直接到交付稿。 |
| **D3** | 全链路无脚本把 `01c.typography.source` 写回 `metadata.style_source`；④ gate 要求两边都非空才比对 | **style_source 一致性检查空转**。`metadata.style_source` 永远空，条件永不成立，"不一致即阻断"形同虚设。 |
| **D10(原D8升级)** | ④ gate 解析 expired 失败时按"无 expired"放行 | 叠加 C5，expired 联动在"读不到"和"解析失败"两个方向都放行。 |

> P0 的共同根因：②③④ 是分发式（无编排）多脚本，跨脚本靠 JSON 字段契约通信，但**没有统一的字段契约测试**——② 写的形状和 ④ 读的形状对不上，靠人肉读才发现。建议补一个"跨脚本契约冒烟测试"（喂一份含 expired/draft/缺章的最小样例，验证 ④ 真的会阻断）。

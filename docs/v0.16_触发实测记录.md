# 五技能触发实测记录（阶段 0 验收第 1、2 条）

> 日期：2026-10-17｜被测版本：⓪ v1.4.0 / ① v0.1.1→0.1.2 / ②③④ v0.1.0→0.1.1
> 判据来源：计划书 §11.1 第 1、2 条（"五技能均能被平台识别加载"、"同一句话不会命中两个技能"，后者含计划书 §3.7 三条硬指标，**任一失败即阻断阶段 0**）

## 一、方法与效力边界（先说清楚这不等于端到端实测）

| 环节 | 本次做法 | 效力 |
|---|---|---|
| 平台是否识别加载 | 装入 `~/.workbuddy/skills/` 后，新建独立上下文子代理，**它能在注入清单中列出 4 个 `bid-*` 技能** | ✅ 已验证：新会话会加载 |
| description 注入内容 | 子代理回贴注入文本，**发现平台注入时按约 40 字截断**（末尾以 `…` 结尾） | ⚠️ 截断事实须记录 |
| 路由判定 | 子代理按完整 frontmatter 判断 8 句语料命中谁 | ⚠️ **独立模型静态判定，非平台真实路由** |
| 真实端到端 | 需用户在新会话逐句发送、观察实际加载 | ❌ **未做，留待用户复核** |

**结论口径**：本次可确认"技能被识别加载"与"完整 description 下语义边界不重叠"；**不能**确认"任何模型、任何措辞下都不重叠"。文档中不得写成"已通过平台实测"。

## 二、四轮结果（含两次无效，不删）

| 轮次 | 做法 | 结果 | 是否有效 |
|---|---|---|---|
| 1 | 由我口述技能定位，子代理判 8 句 | **2 处多命中**：#1「帮我写投标文件」→①+③；#3「投标文件格式章有什么要求」→⓪+④ | ✅ 有效（暴露真问题） |
| 2 | 只给注入的截断 description | 0 多命中 | ❌ **无效**：子代理明说"description 被截断成 `…`，边界无法判断"，加在末尾的排他句它没看到 |
| 3 | 子代理读完整 frontmatter | 0 多命中，但指出"边界句不足以排除 #1/#3"，给了 6 条缺口 | ❌ **无效**：运行目录未同步（`&&` 链因前一条检查返回 1 而短路），它读的是旧 description |
| 4 | 同步后重读完整 frontmatter，先原文回贴再判 | **0 多命中**，且回贴内容含新边界句 | ✅ 有效 |

## 三、第 1 轮暴露的问题与修法

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 「帮我写投标文件」→ ①+③ | ③ 只有"写技术标/方案/施工组织设计"等触发语，无一句把"整套投标文件"排除；"须已有任务卡"只写在正文，description 层没有 | ③ description 增「**须已有任务卡（03_bid-plan.json），只承接单章成文**」「**不写整套投标文件、不写商务标/资格标/报价表**」「用户说…属全流程入口，不属本技能」 |
| 2 | 「投标文件格式章有什么要求」→ ⓪+④ | ④ 正向句"按招标要求的**排版参数**生成样式档"让"格式章"看起来归它管；否定句只覆盖"改内容/判合规/未过 G5 导出"，挡不住问答 | ④ description 增「**须已有成稿**」「用户问"投标文件格式章有什么要求""格式怎么规定的"属招标文件解读（tender-document-review），本技能不做解读」 |
| 3 | ① 自身表述含糊 | "按招标'投标文件格式'章生成章节树"，读者分不清读原文还是读 `01c` | ① 改为「按 01c 格式章的章节树分配篇幅（**章名逐字取自 01c，不回读招标原文**）」 |
| 4 | ② 与 ④ 存在与 ⓪ 抢触发的裸词 | ② 写"投标文件合规自检"、④ 写"投标文件排版""把标书装订成 PDF" | ② 改"投标响应合规自检"；④ 改"投标材料排版"、触发语改"把成稿装订成 PDF"（与 ⓪ 已删的裸词口径一致，见计划书 §3.7） |

## 五、残余风险（不掩盖）

1. **#4 与 #8 靠"动作词"划界，仍不牢**：② 的"检查废标项"与 ⓪ 的"看废标点"只差一个动词；① 的"看还缺什么材料"与 ② 的"看看有没有漏响应"都盖"漏项"。本次未多命中，但换措辞可能翻车。**未改**——再改会把 description 写成免责声明，反而降低可用性；留待阶段 2 用真实语料观察。
2. **注入截断**：平台注入 description 时约 40 字后截断。若真实路由也只读截断部分，则本次加在**末尾**的排他边界可能不生效——这是本轮最重要的未解风险，须用户在新会话用第 1、3 句亲自验一次。
3. **模型依赖**：判定随模型变化。本记录只对"做判定的那个模型"成立，换模型需重测。

## 六、装入与卸载

- 装入：4 个技能复制至 `~/.workbuddy/skills/`，逐目录 `diff -r` 与仓库一致。
- 卸载：按既定方案**只留 ①**，移除 ②③④。理由：① 的降级行为是"指路"（无 `01_tender-facts.json` → 请先执行招标解读），对用户有用；②③④ 的降级行为是"能力未实现"，且会抢 ⓪ 的活。仓库四份均保留，待阶段 1/2/3 各自上线再装。

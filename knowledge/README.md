# knowledge/ —— 跨项目素材母库（M2b）

> 版本：v1（repo/v1.7.32 结构落成）｜定位：投标五技能链 ③ `bid-technical-proposal` 的叙述素材来源
> 性质：**仓库级资产**（不在 `skills/` 下、不进 `skills-lock.json`）；条目内容按业态持续补充，本文件管结构与纪律
> 结构先行（用户 2026-10-21 拍板）：结构领域中立，不预设风电/光伏术语——新能源只是填充期业态之一

## 一、定位与边界：素材收"叙述"，不收"事实"

| | 素材库（本目录 → 项目 02b_knowledge） | 事实库（02_facts） |
|---|---|---|
| 内容 | 同类工程经验、专项工艺、保证措施、服务承诺、技术路线素材 | 资质证书号、业绩合同额、人员证号、设备参数、财务数 |
| 性质 | 可改写、可组合、可按项目调整 | 逐字引用，不可改写 |
| 写错后果 | 扣分 | 提供虚假材料 |

## 二、两级库关系（快照语义，计划书 §6.3）

- 本目录 = **跨项目母库**，只由维护人维护，长期积累，不随项目变；
- `<项目>/bid/02b_knowledge/` = 本次项目从母库**复制＋挑选**出的素材快照，③ **只读这一份**；
- ③ 永不直读母库：母库持续增删，直读会导致两次生成读到不同素材、产物不可复现。

## 三、目录结构（按素材类别分层，业态/地区走 tags）

```
knowledge/
├── README.md            # 本文件：入库规范
├── tags词表.md          # 受控 tags 词表（词表外红灯）
├── 素材条目模板.md       # 条目模板
├── 01-同类工程经验/      # 已建工程实施经验叙述
├── 02-专项工艺/          # 具体工艺做法（流程/要点/通病防治）
├── 03-保证措施/          # 质量/安全/进度/资源/环保水保措施
├── 04-服务承诺/          # 售后、质保期服务、运维响应
└── 05-技术路线/          # 真实用过的设计/技术路线叙述（铁律 8 的来源）
```

通用素材（如质量管理措施）天然跨业态——靠 tags 检索路由，不靠目录。**不按业态分目录**（v0.20 拍板：避免通用素材被逼复制两份或无处安放）。

## 四、条目契约（frontmatter）

③ 契约五字段（`skills/bid-technical-proposal/assets/knowledge.schema.yaml` 0.1，必填）：

`id / title / use_when / tags / verifiable_facts`

母库附加三字段（**本 README 约定层，非 ③ 契约**；复制进 02b 时保留，③ 校验只认五字段、多余字段无害兼容）：

| 字段 | 必填 | 说明 |
|---|---|---|
| source | 是 | 来源文档（历史标书名/专项方案名/工法编号），可追溯 |
| updated_at | 是 | 最近核验日期（YYYY-MM-DD）；超 12 个月 `check_knowledge.py` 出 W 级提示（R8） |
| owner | 是 | 录入责任人 |

写法约束：列表一律行内写法（`tags: [风电, 基础施工]`）；机检解析器为纯标准库轻量实现，**不支持块状列表**。

## 五、入库流程与拆条粒度

1. 各业务口提交原始材料（历史标书/专项方案/工法/运维总结）；
2. 维护人拆条清洗：一条 = **一组触发条件（use_when）＋ 一个做法单元**，正文 300–800 字为宜；多场景拆多条，不写"大而全"；
3. 跑 `python tests/check_knowledge.py` 全绿后入库提交。

## 六、敏感信息与事实清洗（红线，违反即不入库）

- **可核查事实不得留在素材正文**：报价、合同额、证书编号、人员姓名＋证号、具体日期、专利数量等 → 要么抽成 `verifiable_facts` 引用（值以事实库为准），要么删除；
- `verifiable_facts` 为空但正文出现上述内容 = 违约（机检抽检＋人工复核双保险）；
- 商业机密与未公开项目数据不入库；
- 历史标书**整段搬运前必须清洗**——标书原文天然夹带事实，这是最大的入库风险点。

## 七、tags 受控词表

- 标签一律从 `tags词表.md`（v1）取值，**词表外红灯**；
- 新增标签 = 维护人先改词表、再入库条目（同一次提交），防止"风电/风力发电"式漂移；
- 一个条目至少 1 个（契约），建议四维各 1–2 个。

## 八、id 编号规则

- `kn-001` 起全局连续分配，只增不回收、跳号不复用（与 ③ 契约 `^kn-\d{3,}$` 一致）；
- 文件名 = `kn-XXX_标题.md`，frontmatter id 必须与文件名前缀一致（机检 K9）。

## 九、机检

```powershell
python tests/check_knowledge.py     # 空库绿；条目违约 rc=1；超 12 个月素材 W 级提示（R8）
```

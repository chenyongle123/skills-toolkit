# 流水线交接约定（分发式状态机）

> 版本：0.1.0（阶段 0）
> 适用范围：① `bid-response-plan`、② `bid-compliance-check`、③ `bid-technical-proposal`、④ `bid-docx-export` **四份逐字一致**；⓪ `tender-document-review` **不复制本文件**，仅在其输出末尾加一行交接提示。
> 一致性校验：四份文件 `sha256` 必须相同，由 `tests/validate_contract.py` 校验。**改一份必须四份同改**——改一份忘三份会导致状态判读错位，这是分发式（无编排）架构的固有风险。

---

## 一、唯一状态载体

`<项目>/bid/00_metadata.json`。由 **⓪ 在出口创建**（只写 `stage="reviewed"` 与 `schema_version`，其余字段留空/默认），此后由各技能按本约定改写。结构见 `assets/metadata.schema.json`。

| 字段 | 类型 | 写入者 | 说明 |
|---|---|---|---|
| `schema_version` | string | ⓪ 创建时写入 | 固定 `"0.1"`；结构变更才升 |
| `project` | object | ⓪ 创建，① 可补 | `name` / `no` / `purchaser` |
| `stage` | enum | 见 §二 责任表 | **唯一进度判据**；只允许前进或按规则回退 |
| `bid_mode` | `normal \| blind` | ① 按 ⓪ 产物写入 | 暗标标记；③④ 只读不改 |
| `deadline` | string（ISO 8601 含时区） | **① 在 G2 时人工二次确认后写入** | 时效判定的**唯一依据**；AI 不得从招标文件解析后直接采用 |
| `style_source` | `tender_required \| client_template \| baseline` | ④ 按 `01c.typography.source` 写入 | 与 `01c.typography.source` 不一致即记 `failed_nodes` |
| `skill_versions` | object | 各技能写自己 | 只写**实读** frontmatter 版本，不写常量 |
| `failed_nodes` | array | 各技能 | 校验失败的节点名 |
| `retry_count` | integer | ② ③ | 回退计数，上限 2 |
| `exhausted` | boolean | ② | 重试耗尽置 `true`，转人工 |
| `install_mode` | `kit \| standalone` | 首个运行的技能 | 读不到 `skills-lock.json` 记 `standalone`，**不得报错** |
| `warnings` | array | 各技能追加 | 非阻断提示（版本不一致、`expiring_soon`、旧规则产物） |
| `updated_at` | string | 每次写回 | ISO 8601 含时区 |

**硬规定**：`00_metadata.json` 是**唯一**状态载体。不得另建状态文件、不得把进度写在 Markdown 里、不得靠"文件名推断"替代本文件。

## 二、状态机与责任技能

```
reviewed ──G2──► facts_confirmed ──► planning ──G1──► plan_confirmed
   (⓪)              (①)                (①)               (①)
                                                          │
                                                          ▼
                                                     checking ──G3──► check_confirmed
                                                        (②)              (②)
                                                                           │
                                                                           ▼
                     writing ◄──G4(首章)── route_confirmed ◄──────────────┘
                       (③)                   (③)
                        │  ▲ 回退≤2轮（改正文）
                        ▼  │
                    rechecking ──► recheck_confirmed ──G5──► exported
                       (②)              (②)                 (④)
                        │
                        └── 重试耗尽 ──► exhausted（转人工）
```

| `stage` | 含义 | 写入者 | 允许的下一状态 |
|---|---|---|---|
| `reviewed` | ⓪ 完成解读，产物齐备 | ⓪ | `facts_confirmed` |
| `facts_confirmed` | G2 通过：事实库经人工确认完整准确 | ① | `planning` |
| `planning` | ① 正在生成任务卡与目录骨架 | ① | `plan_confirmed` |
| `plan_confirmed` | G1 通过：章名、顺序、篇幅分配经人工确认 | ① | `checking` |
| `checking` | ②-A 覆盖检查执行中 | ② | `check_confirmed` |
| `check_confirmed` | G3 通过：废标报告逐条处置完毕 | ② | `route_confirmed` |
| `route_confirmed` | 首章 G4 通过：技术路线经人工确认 | ③ | `writing` |
| `writing` | ③ 逐章成文中（每章动笔前各过一次 G4） | ③ | `rechecking` |
| `rechecking` | ②-B 响应检查执行中 | ② | `recheck_confirmed` |
| `recheck_confirmed` | G5 通过：成稿终检与背对背复核完成 | ② | `exported` |
| `exported` | ④ 导出完成 | ④ | — |
| `exhausted` | 重试耗尽，转人工 | ②③ | 人工重置 |

**回退规则**：

| 场景 | 回退到 | 上限 | 回退时刷新什么 | 不刷新什么 |
|---|---|---|---|---|
| ②-A 发现事实库缺项（`fact_missing`） | `facts_confirmed`（交 ① 补录） | 2 轮 | 任务卡状态、②-A 报告 | ⓪ 的 `01` / `01b` / `01c` |
| ②-B 检出重大未响应或跨章不一致 | `writing`（交 ③ 改正文） | 2 轮 | ③ 草稿、②-B 报告 | `01` / `01b` / `01c` / `02` / `02b` / `03` / `04` |

## 三、入口校验（四步，缺一即拒）

1. **定位状态文件**：`<项目>/bid/00_metadata.json` 不存在 → 阻断，提示"请先执行 ⓪ 招标解读（tender-document-review），产出 `01_tender-facts.json` 与 `00_metadata.json`"。
2. **校验 stage**：实读值不在本技能允许的前置集合内 → 阻断，同时打印实读值与期望值。
3. **校验前置产物**：逐个检查文件存在、非空、可解析；任一不满足 → 阻断并列出缺件清单。
4. **校验契约版本**：
   - `contract_schema_version` **等值校验**，不等即阻断（结构漂移）；
   - `source_skill_version` 按 **semver 三档**：major 高于当前 → 阻断；minor 高于当前 → 告警写 `warnings[]`，不阻断；patch 差异 → 静默。

### 各技能前置集合

| 技能 | 允许的 `stage` | 前置产物（缺一即拒） |
|---|---|---|
| ① `bid-response-plan` | `reviewed` | `00_metadata.json`、`01_tender-facts.json`、`02_facts.(md\|yaml)`（事实库可缺，但缺则任务卡全 `blocked_by_facts`，须显式告警） |
| ② `bid-compliance-check`（②-A） | `plan_confirmed` | `01_tender-facts.json`、`01b_spec-items.json`、`01c_format-outline.json`、`03_bid-plan.json`、`04_outline.json`、`02_facts` |
| ② `bid-compliance-check`（②-B） | `writing` | 上述全部 ＋ `05_chapters/*.md` |
| ③ `bid-technical-proposal` | `check_confirmed` | `01`、`01b`、`01c`、`03_bid-plan.json`、`04_outline.json`、`02_facts`、`02b_knowledge/` |
| ④ `bid-docx-export` | `recheck_confirmed` | `05_chapters/*.md`、`01c_format-outline.json`、`06_compliance/`（含 `form-check.md`、`consistency-issues.md`——后者由 ②-B 阶段 2 产出，未到阶段缺失不按缺件拒）、`03b_evidence-index.json` |

**②③④ 一律不读招标文件原文**。需要原文级信息时，只能取自 `01` / `01b` / `01c` / `03c`；字段缺失即判 `blocked_by_contract`，指回 ① 补充抽取，**不得自己去翻原文**。

## 四、阻断输出格式（不得产出半成品）

前置缺失或 stage 不符时，**只输出下列结构，不产出任何成果文件**：

```
【执行阻断】<技能名> 未执行
原因：<缺失项或 stage 不符>
当前 stage：<实读值>；本技能要求：<允许集合>
缺少产物：<逐条列路径>
处置：请先执行 <技能名>（<做什么>），产出 <产物路径> 后重试本技能
```

**硬规定**：一旦产出半成品，跳过的人不会知道自己在用残件。宁可阻断，不可"先出一版"。

---

## 五、出口写回（五项必写）

正常结束时，必须写回 `00_metadata.json`：

1. `stage` → 本技能完成任务对应的状态；
2. 产物路径（写入本技能 SKILL.md 指定的字段或 `warnings[]` 之外的固定键）；
3. `skill_versions[<本技能 name>]` → **实读** frontmatter `version`；
4. `updated_at` → 当前时间（ISO 8601 含时区）；
5. `warnings[]` / `failed_nodes[]` → 本次新增项（告警数一并打印）。

并打印交接提示：

```
下一步：调用 <技能名>，输入 <产物路径>
关卡：<Gx>（需人工确认：<具体确认什么>）
```

## 六、五人关卡归属（未过关卡不得写下一 stage）

| 关卡 | 位置 | 人确认什么 | 通过后写入的 stage |
|---|---|---|---|
| **G2** | ① 入口 | 投标人事实库完整准确（Skill 绝不代填） | `facts_confirmed` |
| **G1** | ① 出口 | 目录骨架的章节名/顺序、篇幅分配 | `plan_confirmed` |
| **G3** | ②-A 出口 | 废标报告的"响应不足/未响应/需原件核对"逐条处置 | `check_confirmed` |
| **G4** | ③ 每章动笔前 | 技术路线、实现架构、工艺选择是否为企业真实采用 | `route_confirmed`（首章）／保持 `writing`（后续章） |
| **G5** | ②-B 出口 | 背对背独立复核差异清单闭环、跨章不一致、暗标终检、独立性自查 | `recheck_confirmed` |

**关卡不得自我批准**：AI 只能输出"待人工确认"并停住，不得以"已确认"写入 stage。

## 七、版本自检（三级降级，不得阻断）

读套件根 `skills-lock.json`：

| 读到什么 | 行为 |
|---|---|
| 找到 lock，自身 `version` 与 `hash` 均一致 | 静默通过 |
| 找到 lock，但 `version` 或 `hash` 不一致 | **告警**"组件版本不一致，建议同步"，写 `00_metadata.warnings[]`，**不阻断** |
| 找不到 lock（技能被单独安装） | **静默跳过**，`install_mode` 记 `standalone` |

**自检是提示机制，不是门禁**。"独立安装"是本套件的设计目标之一。

---

## 八、禁止事项

1. **不得跳级**：stage 不满足即拒，不得"看着差不多就往下做"。
2. **不得改写他人负责的 stage**：只写本技能责任表内的状态。
3. **不得静默跳过**：缺前置必须阻断并说明，不得以"默认值"糊过去。
4. **不得产出半成品**：阻断即零产物。
5. **不得绕过 ⓪ 读原文**：单一真源，②③④ 无原文读取授权（唯一例外见各技能 SKILL.md 的"接缝例外"声明，且仅限条目结构与标题层级）。
6. **不得代填**：事实库、金额、投标决策一律不代填、不代算、不代定。

# 投标技术标正文（套件第 ③ 环）

> **技能版本：v0.3.1（2026-10-21；专家复核批次 3–4 文档统一：入口校验「四步」→「五步」计数修正、去「骨架版」陈旧措辞〔check_consistency 已 v0.4.0 实装〕；`word_count.py` MISSING/孤儿 rc=1〔C12〕）。0.3.0（阶段 5：新增 `SKILL.lite.md` L0 纯对话版轻量提示词——五步循环单章成文每步【能力依赖：L2】+降级指令、铁律自包含、R7 状态快照、强制"一章一轮"；与主文件铁律逐字一致由 `validate_contract` C13 机检；计划书 §9／§11.6）。0.2.0（阶段 2 正文能力版；0.1.1 历史＝入口校验＋状态读写，曾修 description 排他边界）**
> 本版能力范围见 §七；五步循环**操作细则**以 `references/章节写作五步循环.md` 为准，本文件只列步骤表。
> 受套件总则（8 条铁律）约束；流水线状态机见 `references/流水线交接约定.md`。

## 一、定位与边界

**一句话**：一次只写一章、一章一次确认；**技术路线没经人确认，不动笔**。

| 做 | 不做 |
|---|---|
| 按 `03_bid-plan.json` 的任务卡逐章成文，每段标 `[[F:facts-id]]` / `[[S:评分点-id]]` | 判定是否废标、是否偏离（属 ②） |
| 从 `02_facts` 取可核查事实（逐字引用，不改写） | 改动章节名与顺序（属铁律 2） |
| 从 `02b_knowledge` 取可改写素材（可组合、可调整） | 自行推演技术路线（无来源即输出"待确认"） |
| 逐章过 G4，再进下一章 | 排版导出（属 ④） |
| 每章完稿自检（`check_facts.py` rc=1 不得交复核；`word_count.py` 对照篇幅） | 自查跨章一致性（属 ②-B `check_consistency.py` 唯一实现） |

**素材路由边界**：只读本次项目的 `02b_knowledge/` 快照，**不直读跨项目母库**——母库持续增删，两次生成会读到不同素材，产物不可复现。

## 二、入口校验（五步，缺一即拒）

1. `00_metadata.json` 存在；`stage` 必须为 **`check_confirmed`**。
2. 前置产物：`01`、`01b`、`01c`、`03_bid-plan.json`、`04_outline.json`、`02_facts`、`02b_knowledge/`（缺任一即阻断，指路对应技能）。
3. 校验 `04_outline.json` 的章节名与 `01c.chapters[].title` **逐字一致**；不一致即阻断（不得自行"对齐"）。
4. `01.contract_schema_version` 等值校验；`source_skill_version` semver 三档。
5. 读 `bid_mode`（只读不改）：`blind` 时全程叠加 `references/暗标写作规范.md`（身份禁项对照 `01c.typography.identity_ban`）。

## 三、五步循环（v0.2.0 已实装；操作细则见 `references/章节写作五步循环.md`）

| 步 | 动作 | 产出 | 卡点 |
|---|---|---|---|
| 1 | 读任务卡，取本章评分点/条款/响应形式 | 本章要求清单 | 缺任务卡即拒；`blocked_by_facts`／`blocked_by_clarify` 卡只出占位并指路回退 |
| 2 | 素材路由（只读 `02b_knowledge/` 快照，按 `use_when`/`tags` 匹配）＋从 `02_facts` 取事实（逐字引用） | 素材与事实候选 | 无素材只写占位，不得自造；素材涉可核查事实时数值回事实库取 |
| 3 | **确认框架与技术路线**：`route_summary` 3–5 条、逐条注来源 | 本章思路 | **G4：人确认；AI 起草的路线一律在此否决或替换；未过 G4 不动笔** |
| 4 | 按章撰写（服从 `写作规范.md`／`图表与题注规范.md`／暗标叠加），每段标 `[[F:]]`/`[[S:]]`；跑 `scripts/check_facts.py`＋`scripts/word_count.py` 自检 | 章节草稿（frontmatter `status: draft`） | 无来源段落不得留；check_facts rc=1 不得交复核 |
| 5 | **背对背复核**（复核人不看本稿，只对照 `01`/`01b`/`01c` 与原文重查，产出独立差异清单） | 定稿（`status: final`；`04_outline` 节点 `status: done`） | 未核不得进装配 |

**强制"一章一轮"**：未过 G4 不得进下一章；不得一次生成整本。首章 G4 通过写 `route_confirmed`，随后 `writing`；后续章 G4 通过保持 `writing`。章节产物契约（frontmatter 字段）见 `assets/chapter.schema.json`；文件名 = `<chapter_id>.md`（可加中文后缀）。

## 四、铁律（八条，与 ①②④ 逐字一致）

<!-- IRONLAWS:BEGIN -->
1. **不编造事实**：业绩、人员、证书、参数、金额、工期，未见于事实库即写 `【待填：××】`；素材库内容可改写，但不得产出任何可核查事实。
   - **扫描件不作事实来源**：营业执照、资质证书、合同扫描件只作证明材料，证书编号、有效期、合同额等一律由知识库维护人录入事实库；**AI 不得从扫描件 OCR 后直接填表**——OCR 错一位数字即构成提供虚假材料。
   - **图文不符时以事实库为准并报警**：发现扫描件与事实库不一致，输出`待核`，不自动择一。
2. **不改章节名与顺序**：章节名一律取自 `01c`，逐字不改；格式废标优先于得分优化。
3. **暗标匿名与页数上限**：暗标项目全文不得出现投标人名称、标识、人员姓名及其他可识别信息；**无论是否暗标，正文 + 证据的总页数均不得超出 `01c.typography.page_limit`**（未载明上限时按招标的隐含要求估算并写明依据）。
4. **不给法律结论**：不判定"是否废标""是否违法"，只报事实态。
5. **不代投标人决策**：投标与否、报价几何、让不让步，不给建议。
6. **不做未授权承诺**：技术参数、工期、售后承诺必须来自事实库或用户明示。
7. **每段可回溯**：无来源的段落不得进入交付稿。
8. **技术路线须有来源** ★：技术路线、实现架构、工艺选择、设备选型必须来自 `02_facts`、`02b_knowledge` 或用户明示。**AI 自行推演出的路线即使看起来合理，也不得进入交付稿**——路线错了不是改几句话能补的，只能重写。无来源时输出 `【待确认：技术路线】`，交 G4 关卡由人定。
<!-- IRONLAWS:END -->

> 反例见 `references/常见错误.md`；尤其注意反例 7（无来源段落）与反例 8（自推技术路线）。

## 五、交接

- 按 `references/流水线交接约定.md` 读写状态；**G4 不得自我批准**：只能输出"待人工确认"并停住。
- **本技能出口**：全部章节定稿（frontmatter `status: final` 且 `04_outline` 节点全 `done`）后，`stage` 保持 `writing`（②-B 的入口态），打印：

```
下一步：调用 bid-compliance-check（②-B 响应检查），输入 05_chapters/*.md
关卡：G5 在 ②-B 出口（成稿终检）
```

- 跨章一致性**不在本技能实现**：归属 ②-B 的 `check_consistency.py`（全套件唯一实现；v0.4.0 实装——位置粒度「章节·段落·行号·原文片段」＋工期/金额同语义多值 ⚠️＋关键日期槽（截止/开标/递交/有效期）多值 ⚠️＋同值异形不误报），成稿后由 ②-B 调用；本技能不复制一份，避免双实现漂移。

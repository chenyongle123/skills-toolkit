# 废标项比对方法（②-A · A 类）

> **依据**：计划书 §4.3 A 类、计划书 §11.2 验收口径；② SKILL.md 第三节检查类表。
> **适用**：②-A（`stage = plan_confirmed`），在任务卡生成后、交 G3 前执行。
> **口径**：**只报"未响应 / 响应不足 / 有直接卡"，不判"是否废标"**——判废标权在评标委员会（铁律 4）。

## 一、输入与边界

| 项 | 来源 | 说明 |
|---|---|---|
| 废标/否决项清单 | `01_tender-facts.json` 的 `clauses[]` 中 `review_stage = waste` 与 `category` ③ | **不读招标原文**；清单以 ⓪ 抽取为准 |
| 资格项清单 | 同上，`category` ② / `review_stage = qualification` | 资格硬伤提示止损，不计废标风险条数 |
| 任务卡 | `03_bid-plan.json` 的 `items[]` | 每卡有 `source_ref`（条款 id 或 bf id）与 `chapter_id` |
| 章节骨架 | `04_outline.json` / `01c_format-outline.json` | 解析卡 `chapter_id` 是否落到真实章节 |

**缺失即阻断**：任一输入缺失或 `source_ref` 无法解析，报 `blocked_by_contract` 并指回 ①，**不得自行翻原文补**。

## 二、主覆盖比对（逐条闭合）

1. 遍历 `clauses[]` 中 ② 类与 ③ 类每一条，在 `items[]` 中找 `source_ref` 精确匹配的任务卡；
2. 命中 → 记"有卡"，并核对卡的 `response_form` 与该条款性质相符（声明类→letter，表格类→table，材料类→scan）；
3. 未命中 → 记"无卡（未响应）"，**按条款后果分级列示**（`consequence` 字段照录，不自行升级/降级）；
4. 反向遍历：任务卡 `source_ref` 解析不到任何条款/评分项/表单的 → 记"孤儿卡"。

**判定口径**：

| 状态 | 含义 | 出口动作 |
|---|---|---|
| 有卡 | 条款有对应响应动作 | 通过 |
| 无卡 | 条款无任何响应动作 | 记入 G3 差异清单，逐条人工处置 |
| 孤儿卡 | 卡不指向任何上游条目 | 人工甄别成因（见下） |

## 三、跨类否决级条款补充扫描（M1）

③ 类之外，**①②④⑤⑥⑦ 类中带否决级后果**的条款（`consequence` 含"否决/废标/无效"）也须扫描一遍，按 `source_ref` 精确匹配列任务卡覆盖。此列为**非主覆盖口径**，不单独阻断 G3。

**「无直接卡」的四类常见成因，须人工甄别、不当作缺口**：

1. 与 ③ 类某条重复，该条已有卡（如限价条款 c-0035 ↔ c-0020）；
2. 经商务表 bf 卡覆盖，但 `source_ref` 记 bf-ID 非 clause-ID（如保证金否决 ↔ bf-02）；
3. 属 ④ 排版职责（签章/装订/密封/份数）；
4. 流程/时限项，靠操作不靠文档响应（逾期拒收、拒签合同）。

## 四、输出

写入 `06_compliance/compliance-report.md`（A 类节）：

- 覆盖统计：③ 类总数 / 有卡 / 无卡；② 类同；
- 无卡条款逐条清单：`clause_id`、类、事项、后果（照录）、建议动作；
- 孤儿卡清单；
- **G3 提示**：未逐条人工确认前，不得写 `check_confirmed`。

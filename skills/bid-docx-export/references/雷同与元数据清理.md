# 雷同与元数据清理（④ 导出侧执行口径）

> **依据**：计划书 §8.6（雷同风险与元数据）、§8.6.3（三道防线分工）、§11.3 验收；
> **分工**：雷同**信号判定**归 ②（`references/雷同自查清单.md`，G5 环节人工执行）；④ 只负责**元数据清理**与**暗标标识扫描**的执行，不改任何正文内容。

## 一、四道防线中 ④ 的责任（计划书 §8.6.3）

| 防线 | 责任方 | ④ 的动作 |
|---|---|---|
| 一、素材驱动差异化 | ③ | 不涉及 |
| 二、结构去模板化 | ③ | 不涉及 |
| 三、元数据清理 | **④** | `scrub_metadata.py`（本文 §二） |
| 四、交付前自查 | ② | 输出 `similarity-check.md`（本文 §四 只定格式约束） |

## 二、元数据清理两模式（`scrub_metadata.py`，装配前执行）

| 字段 | 普通标 | 暗标 |
|---|---|---|
| creator / lastModifiedBy | 清空 | 清空 |
| Company / Template / attachedTemplate | 清空 | 清空 |
| lastPrinted / custom.xml / comments | 清空或剔除 | 清空或剔除 |
| 修订记录（w:ins/w:del） | **不自动接受**，存在即 rc=1 | 同左（接受会改内容，归人工） |
| 页眉页脚单位名/LOGO | **保留**（合法展示） | 扫描，命中即 rc=1 |
| PDF `/Info` 对象 | 清空 | 清空＋扫描标识串 |

- **修订记录红线**：自动接受修订等于改内容，与「④ 只改外观」的定位冲突——必须回 G5 由人工处置。
- 暗标标识串来源：`--identity "公司名,人名"`（缺省读 `metadata`/调用方透传）；命中只**报事实态**，改写正文归 ③。

## 三、回读校验联动（`verify_docx.py`）

清理由 verify 复核：元数据残留（含修订记录）、暗标标识（正文/页眉页脚/属性三处）、占位符残留、页数闭合——任一残留即 rc=1，`stage` 不写 `exported`。人为在 docx 属性写入一个公司名，verify 必须检出（§11.3 验收第 5.3 条）。

## 四、similarity-check.md 的格式约束（② 人工输出，④ 只约束格式）

- 每条信号给**位置**（章·节·段）＋**模式类型**（套话密度/结构模板化）＋**原文片段**；
- **不得出现「是否构成串标」的定性结论**——判权在行政监督部门，本套件只降概率、不承诺免责（同 ② 清单口径）。

## 五、验收对照（§11.3）

1. 普通标导出后：元数据字段全部为空或已替换，页眉页脚单位名保留；
2. 暗标导出后：上述字段为空且页眉页脚无单位名、无 LOGO；
3. 注入测试：人为写入公司名 → `verify_docx.py` 必须检出。

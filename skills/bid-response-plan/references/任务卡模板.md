# 任务卡模板（① 规则文件）

> 契约：`assets/bid-plan.schema.json` **0.2**。本文件定义建卡规则；字段合法性以 schema 为准。
> 被引用位置：① `SKILL.md` §三主流程第 5 步。实现：`scripts/build_bid_plan.py` 的 `build_03()`。

## 一、文件结构（bid-plan 0.2）

```json
{
  "schema_version": "0.2",
  "preconditions": [ { "id": "p-0001", "item": "补遗/澄清文件对照",
                       "result": "unknown", "evidence": "…", "blocking": true } ],
  "items": [ { "id": "t-0001", "source_type": "scoring", "source_ref": "S-01",
               "chapter_id": "n-1001", "response_form": "text", "word_target": 18000,
               "required_facts": [], "owner": "", "status": "blocked_by_facts",
               "notes": "…" } ],
  "coverage": { "scoring_total": 3, "mapped": 3, "unmapped": [] }
}
```

- `preconditions` 为**顶层字段**，不进 `items`、不进 `required`（向后兼容设计）；
- `items[]` 10 字段**全部 required**：`id / source_type / source_ref / chapter_id /
  response_form / word_target / required_facts / owner / status / notes`。

## 二、`source_type` 四值与建卡规则

| 值 | 建卡对象 | 编号口径 |
|---|---|---|
| `scoring` | 评分点：聚合卡（`S-01/02/03`，对应 `01.scoring.items`）+ 明细子卡（`T3-*`/`T4-*`/`T5-*` 逐行） | 聚合卡 id 取上游评分点编号；子卡 id 取评分表行号 |
| `waste` | 废标/否决条款逐条一卡 | `source_ref` 取 `clauses[].id`（`c-xxxx`） |
| `qualification` | 资格条件逐条一卡 | 同上 |
| `business` | 商务表格/函件逐件一卡 | `bf-01`~`bf-24`，与 `03c` 逐件对应 |

- **明细子卡仅作细化覆盖，不计入 `coverage.mapped`**（避免与聚合卡双计）；
- `coverage.unmapped` 必须为空数组才可交 G1。

## 三、其余字段口径

| 字段 | 规则 |
|---|---|
| `chapter_id` | 必须解析到 `01c_format-outline.json` 的章节 id；解析不到即构建失败 |
| `response_form` | 五值：`letter`（函件）/ `table`（表格）/ `scan`（扫描件证明）/ `text`（正文成文）/ `business_form`（商务表单合集） |
| `word_target` | 明细子卡 `= max(300, round(分值×350))`；聚合卡按分值权重；商务表按表复杂度定 |
| `required_facts` | 所需事实库 id 列表（如 `qual-001`/`perf-001`/`fin-2022`）；空数组 = 不依赖事实库 |
| `owner` | **空串**：责任人由投标人指定，AI 不指派 |
| `status` | 三态：`ready`（可立即编制）/ `blocked_by_facts`（事实库缺条目）/ `blocked_by_clarify`（须投标前书面澄清） |
| `notes` | 一句话说明卡点；涉分值/后果的照录上游数字 |

## 四、`preconditions`（p-0001 恒为补遗对照）

- `p-0001` = 「补遗/澄清文件对照」，**每份 plan 必有且仅有这一条**；
- `result` 三态：`pass`（已逐份核对）/ `fail` / `unknown`（本次未提供补遗文件）；
- `blocking` 恒为 `true`；`result != pass` 时**必须附 `evidence`**；
- **非 pass 即整份阻断**：不得交 G1、不得写 `plan_confirmed`。

## 五、硬性禁止

- 不生成"占位任务卡"凑数；建不了卡的条款进缺口清单，不硬造卡；
- 不为凑 `coverage` 把无对应章节的条款映射到近似章节；
- `word_target` 是**规划值**不是承诺值，③ 成文阶段可据实调整并记录。

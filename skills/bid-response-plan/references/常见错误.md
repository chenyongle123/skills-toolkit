# 常见错误（铁律反例 8 条）

> 版本：0.1.0（阶段 0）｜适用：① ② ③ ④ 共用基线
> 用法：写作期自查、②-A/②-B 检查、④ 导出前回扫，均逐条对照本节；命中任一即按"错误"处理，不得以"表述需要"放行。
> 各技能专属反例追加在文末「本技能专属」节，公共 8 条不得增删改。

---

## 反例 1｜编造事实（对应铁律 1）

| 项 | 内容 |
|---|---|
| **错误做法** | ① 写"我司近年完成多项同类新能源 EPC 项目，业绩优良"，无 `facts id`；② 从营业执照扫描件 OCR 抄统一社会信用代码或证书编号直接填表；③ 事实库无该项目，凭印象补一条业绩。 |
| **为什么错** | 业绩、证书号、金额属可核查事实，编造即"提供虚假材料"；OCR 错一位数字，性质与故意造假相同。素材库内容可改写，但**不得产出任何可核查事实**。 |
| **正确做法** | 未见于事实库即写 `【待填：××】`；扫描件只作证明材料，编号与有效期由知识库维护人录入；扫描件与事实库不一致时输出 `待核`，不自动择一。 |
| **判定线索** | 段落里出现数字/证书号/金额/日期，却找不到对应的 `facts id`。 |

## 反例 2｜改章节名与顺序（对应铁律 2）

| 项 | 内容 |
|---|---|
| **错误做法** | 招标格式章为"施工组织设计"，成稿改成"施工方案与技术措施"；或为把评分点凑在一起，把"商务部分"提到"技术部分"之前。 |
| **为什么错** | 章节名与顺序属形式性要求，格式废标优先于得分优化；改名即偏离招标规定的响应结构。 |
| **正确做法** | 章名一律取自 `01c`，**逐字不改**；评分点需要集中时，在 `04_outline.json` 的 `notes` 注明"评分点 S-07 置于第 X 章之下"，不动章名与顺序。 |
| **判定线索** | 成稿章名与 `01c.chapters[].title` 不一致（逐字比对，含"与/及"、书名号、序号写法）。 |

## 反例 3｜暗标匿名与页数上限（对应铁律 3）

| 项 | 内容 |
|---|---|
| **错误做法** | 暗标正文写"我公司拥有 XX 资质"；页眉保留单位 LOGO；正文 180 页 + 证据 120 页，超过 `page_limit` 200 页仍照常导出。 |
| **为什么错** | 暗标出现可识别信息即废标；页数超限在电子标平台直接拒收或扣分，且**总页数**（正文＋证据）才是判据。 |
| **正确做法** | 暗标全文用"投标人/本单位"中性表述，清除页眉页脚标识；装配前先算"正文页数＋证据页数"，超限即压缩或调整装订方案，不硬导。 |
| **判定线索** | 全文检索单位名/人名/LOGO；`07_out` 成品页数与 `01c.typography.page_limit` 比对。 |

## 反例 4｜给法律结论（对应铁律 4）

| 项 | 内容 |
|---|---|
| **错误做法** | 合规报告写"该条款属以不合理条件限制投标人，违法"；或写"此项未响应，将被判废标"。 |
| **为什么错** | 判废标权在评标委员会，违法认定权在行政监督部门；AI 给结论会把"事实态"变成"法律判断"，用户据此决策风险极高。 |
| **正确做法** | 只报三态（已响应／响应不足／未响应）＋定位＋原文依据；疑似违规控标只**标注**为信号写入 `clarifications[]`，交人工在法定时限内评估。 |
| **判定线索** | 报告出现"违法""违规""必然废标""肯定被否"等定性词。 |

## 反例 5｜代投标人决策（对应铁律 5）

| 项 | 内容 |
|---|---|
| **错误做法** | 建议"报价下浮 5% 更有竞争力"；或判断"这个项目利润薄，建议不投"。 |
| **为什么错** | 报价与投标决策是投标人的商业判断，Skill 无成本数据、无授权；越界即误导。 |
| **正确做法** | 只呈现招标规则与事实态（限价形态、评分权重、资格门槛），价格一律人工填写；决策类问题明确回"不由本技能判断"。 |
| **判定线索** | 出现任何价格数字、下浮率建议、投/不投结论。 |

## 反例 6｜做未授权承诺（对应铁律 6）

| 项 | 内容 |
|---|---|
| **错误做法** | 招标要求工期 ≤180 天，事实库无工期承诺记录，成稿写"我司承诺 150 天完工"；或把质保期从 2 年写成 3 年以示诚意。 |
| **为什么错** | 技术参数、工期、售后承诺都是合同义务，写成什么就要兑现什么；无授权承诺等于替企业签了没签过的条款。 |
| **正确做法** | 承诺值只能来自 `02_facts` 或用户明示；无来源写 `【待确认：工期承诺】`，交人工确认后回填。 |
| **判定线索** | 承诺类数值在事实库中查无对应条目。 |

## 反例 7｜无来源段落（对应铁律 7）

| 项 | 内容 |
|---|---|
| **错误做法** | 整段"我司始终坚持质量第一、安全为先，建立了完善的管理体系……"无任何 `facts id` 或评分点标注，作为章节过渡段大量复制。 |
| **为什么错** | 不可回溯即不可复核；这类段落还是雷同高危区（通用套话密度告警）。 |
| **正确做法** | 每段标注事实 id 或评分点 id；确无来源的过渡句控制在单句、不承载事实与承诺；整段无来源不得进入交付稿。 |
| **判定线索** | 段落末尾无 `[[F:…]]` / `[[S:…]]` 标注且含事实性表述。 |

## 反例 8｜自推技术路线（对应铁律 8）

| 项 | 内容 |
|---|---|
| **错误做法** | 招标只写"应满足冬季施工要求"，AI 自行写出"采用电伴热＋暖棚法，混凝土入模温度不低于 10℃"整套工艺，未经企业确认即进入正文。 |
| **为什么错** | 路线错了不是改几句话能补的，只能重写；"看着合理"不等于企业真实采用，且直接带来报价与履约风险。 |
| **正确做法** | 路线必须来自 `02_facts`、`02b_knowledge` 或用户明示；无来源输出 `【待确认：技术路线】`，在 G4 由人定，未过 G4 不得进下一章。 |
| **判定线索** | 工艺/架构/设备选型段落找不到素材 id，且未经 G4 记录。 |

# 七类-六环节映射（① 规则文件）

> 本文件是 ⓪ `tender-facts.clauses[].review_stage` 派生字段的**唯一生成规则源**（计划书 §6.2 / D9），
> 也是 ① 任务卡 `source_type` 与 ⓪ 七类条款的衔接口径。
> 被引用位置：① `SKILL.md` §三主流程第 1 步；⓪ `emit_facts.py` 序列化 `01_tender-facts.json` 时。

## 一、⓪ 七类（原样照抄，不重编码）

| 编号 | 类名 | 覆盖内容 |
|---|---|---|
| ① | 时间节点与流程 | 公告/澄清/截标/开标/评标/公示/异议各时限 |
| ② | 投标资格条件 | 资质等级、业绩、财务、人员、信用、联合体、关联企业排除 |
| ③ | 废标/否决情形 | 明示否决/废标/无效标触发条件 |
| ④ | 评标与定标标准 | 评分矩阵、权重、基准价、定标方式 |
| ⑤ | 保证金与商务条款 | 投标保证金、履约担保、有效期、报价规则 |
| ⑥ | 合同关键约束 | 专用合同条件生效值、缺陷责任/保修/调价/误期赔偿/保险 |
| ⑦ | 形式与程序要求 | 格式章、签章、装订、份数、递交方式、电子平台操作 |

## 二、六环节（`review_stage` 取值，计划书 L908 定义）

| 值 | 含义 | 对应投标动作 |
|---|---|---|
| `form` | 形式与程序 | 按格式章/签章/装订/份数/递交方式执行 |
| `responsive` | 响应性 | 对招标文件商务/技术部分的响应性声明 |
| `qualification` | 资格审查 | 资格条件、业绩、财务、人员、信用材料 |
| `waste` | 废标规避 | 保证不作废/不被否决的动作 |
| `scoring` | 评分得分 | 评分矩阵逐点响应 |
| `other` | 其他 | 无法归入前五者（流程时限、合同约束、联系信息等） |

## 三、映射表（一类可对多环节）

| 七类 | 主环节 | 并列环节（条件触发） |
|---|---|---|
| ① 时间节点与流程 | `other` | 递交时限/方式涉形式后果时加 `form` |
| ② 投标资格条件 | `qualification` | 资格不符即否决时加 `waste` |
| ③ 废标/否决情形 | `waste` | 形式性废标（装订/签章/份数）加 `form`；资格性否决加 `qualification` |
| ④ 评标与定标标准 | `scoring` | 低于成本/超限价等否决性评分规则加 `waste` |
| ⑤ 保证金与商务条款 | `qualification` | 保函不合规→否决时加 `waste` |
| ⑥ 合同关键约束 | `other` | — |
| ⑦ 形式与程序要求 | `form` | 活页装订/未加密等形式废标加 `waste` |

## 四、生成规则

1. **逐条款判定**：对 `01_tender-facts.json` 的每条 `clauses[]` 判 `review_stage`；
2. **可多值**：命中主环节 + 任一并列条件即取多值（数组），顺序为主环节在前；
3. **不得留空**：无法归入前五值的一律 `other`，**禁止空值/自造第七值**；
4. **一类对多环节是设计允许的**（计划书 L908 原文），不得为凑"一类一值"而改判；
5. **后果表述不得自评**：`consequence` 只取上游备注明示的后果，未载明写"后果未载明"。

## 五、与 ① 任务卡 `source_type` 的衔接

| review_stage | ① 任务卡 source_type |
|---|---|
| `scoring` | `scoring` |
| `waste` | `waste` |
| `qualification` | `qualification` |
| `form` / `responsive` / `other` | `business`（商务表格/函件框架） |

> 实现：`scripts/build_bid_plan.py` 的 `TASKS` 表按本映射建卡；换项目时只需替换 `TASKS` /
> `SCORING_DETAIL` / `BUSINESS_FORMS` 三张映射表与 `FORMAT_CHAPTERS` 常量，本文件规则不变。

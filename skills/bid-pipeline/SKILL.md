# 投标文件全流程编排（套件链首·薄路由）

> **技能版本：v0.1.0**（2026-10-28；首发：计划书 §13 待确认第 2 项拍板落地——以 P2 可选项补一个**纯编排技能，不改动 ⓪①②③④ 逻辑**；① 同步 v0.28.0 让渡「帮我写投标文件」「帮我做投标文件」「做这个标」三个全流程触发短语给本技能）。
> 受套件总则（8 条铁律）约束（同 ⓪ 姿态：不复制铁律块，声明受约束即可）。
> 流水线状态机权威＝①②③④ `references/流水线交接约定.md`（四份逐字一致）；本技能**不复制副本**、**不写 `00_metadata.json` 任何字段**（stage 写入权按责任表归属各技能）。路由细节见 `references/编排路由表.md`，状态判定脚本见 `scripts/pipeline_status.py`。

## 一、定位与边界

**一句话**：接住全流程请求，按状态机把 ⓪①②③④ 串起来推进；**只路由，不代写**。

| 做 | 不做 |
|---|---|
| 判定全流程 vs 单环节请求（单环节让位，见 §五） | 写任何正文/任务卡/报告（归各技能） |
| 引导建立项目工作区 `<项目>/bid/` 与 02_facts/02b 快照 | 写 `00_metadata.json` 的 `stage`（只读状态机） |
| 按当前 stage 调对应技能执行其完整流程 | 跳关卡、代用户确认 G1–G5 |
| 在关卡停等、播报进度、断点续跑（`scripts/pipeline_status.py`） | 商务标/资格标/报价表（链外，只指路不代劳） |
| 终态（`exported`）后核对 verify-report 并汇报收口 | 改任何技能产物的内容 |

**编排零侵入**：本技能不要求 ⓪①②③④ 做任何配合性修改；各技能独立可用性不受影响。弱平台未触发本技能时，链路仍靠「入口拒跳＋出口指路」自洽成立（计划书 §2.1 基线不变）。

## 二、入口判定（触发与排他）

- **接住**（全流程请求）：「帮我写投标文件」「帮我做投标文件」「做这个标」「从招标文件做到导出」，以及语义等价的"把整个标做起来""从头到尾"类表达。
- **不接**（让位，见 §五）：单环节请求——审招标文件（⓪）、排目录/任务卡（①）、查废标/响应检查（②）、写某一章（③）、导出排版（④）。
- **语义模糊时先问一句**：「这次是要我从招标文件一路做到导出，还是只做其中一段？」——不得替用户猜。

## 三、第一步：工作区就绪检查

1. **定位 `<项目>/bid/`**：不存在 → 引导创建（目录名约定见 ① 契约），随后从 ⓪ 开始。
2. **招标文件正本＋全部补遗**：确认位置后**交 ⓪**；本技能不读招标原文（单一真源，铁律同源）。
3. **`02_facts` 项目事实快照**：缺 → 按 `references/编排路由表.md` §五引导建立（两级库语义＋三条红线：AI 只读、不 OCR、录入＝起草→用户逐项确认→落库）。
4. **`02b_knowledge/` 素材快照**：缺 → 引导从素材母库按业态/评分点选拷；可先空目录起步（③ 对缺素材只写占位）。
5. **跑 `scripts/pipeline_status.py --bid <目录>`** 确认起点（新项目：`00_metadata.json` 不存在 → 从 ⓪ 开始）。

## 四、推进循环（stage → 调技能 → 关卡停等 → 再判定）

```
循环：
  1. 跑 pipeline_status.py（或实读 00_metadata.stage）得当前位置与下一步
  2. 调「下一步」技能执行其完整流程（含其入口校验、出口指路）
  3. 该技能到人工关卡（G1–G5）即停等：向用户复述「待确认什么＋确认后会发生什么」，
     等用户明确确认（AI 不得自我批准）
  4. 技能段完成后重读 stage，播报进度，回到 1
停：stage=exported（终态，见 §七）／stage=exhausted（转人工，只播报不推进）
```

- 关卡停等话术、每关确认什么：`references/编排路由表.md` §二。
- 回退/重试耗尽分支：`references/编排路由表.md` §四（照录交接约定 §二）。
- **每轮只推进一个技能段**；一次会话推进多少段由用户关卡确认节奏决定，不得连续吞关卡。

## 五、让位表（单环节请求不接管）

| 用户请求形态 | 让位给 |
|---|---|
| 审招标文件 / 看废标点 / 提取评分项 | ⓪ tender-document-review |
| 帮我编标书 / 排投标目录 / 生成任务卡 | ① bid-response-plan |
| 检查废标项 / 做响应偏离表 / 成稿终检 | ② bid-compliance-check |
| 写这一章 / 按评分点写正文 | ③ bid-technical-proposal |
| 导出 Word / 排版 / 页数超限检查 | ④ bid-docx-export |
| 商务标 / 资格标 / 报价表 | 链外：说明边界后转人工/造价专业 |

## 六、断点恢复

任何新会话（用户说"继续那个标""标做到哪了"）：先跑 `scripts/pipeline_status.py --bid <目录>`（rc 0/1/2 语义见脚本头注），向用户播报「当前位置＋已过关卡＋缺件（若有）＋下一步」，再按 §四继续。**不重跑已达标的段**；缺件（rc=1）先按指路补齐。

## 七、收口（终态 exported）

1. 实读 `07_out/verify-report.md` 逐项结论向用户汇报（残留/不符项为零才算过）；
2. 提示人工终审与交付动作（装订/密封/平台递交属线下流程，不在链内）；
3. 声明链路收口：无下一技能；后续修改从 ②-B（`rechecking`）或 ③ 按需重入。

## 八、契约

| 项 | 值 |
|---|---|
| 读取 | `<项目>/bid/00_metadata.json`（**只读**：stage/bid_mode/deadline/failed_nodes/warnings/retry_count）、`04_outline.json`（只读，进度展示） |
| 产出 | **零文件产物、零写盘**（会话态编排；唯一工具 `scripts/pipeline_status.py` 为只读） |
| 自检 | `pipeline_status.py` 退出码：0=正常路由态（含停等/终态/转人工）；1=stage 达标但里程碑产物缺件（回上游补齐）；2=结构性阻断（无 00_metadata/stage 非法 → 先 ⓪） |
| 边界 | 不读招标原文、不改任何技能产物、不写 stage、不代写内容、不跳关卡；商务标/资格标/报价表链外指路 |

## 【必读】关于"如何被触发"的实测结论（2026-10-10）

> 本节是 5 轮真实实测的结论，**不是推测**。任何使用者（包括 AI 自己）都必须先读这一节。

### 结论一：不存在"自动强制"

Skill 是按 `description` **匹配、按需加载**的，**没有任何设置/文件/hook 能让它"每个任务自动必跑"**。
2026-10-10 曾尝试以下三条路，**全部失败**：

| 尝试 | 结果 |
|---|---|
| 写入 `~/.workbuddy/MEMORY.md` | ❌ 非注入源 |
| 写入 `user-<uid>-personal/MEMORY.md` | ❌ 非注入源 |
| 写入 `~/.workbuddy/memory/<uid>_memory.md` | ❌ 由系统管理，非手改入口 |
| 找 hook / 插件强制 | ❌ WorkBuddy 无此功能 |

**真正的注入源**：`~/.workbuddy/memory/<uid>_memory.md`（系统生成，带 Version + RAW_JSON 结构），
**只能通过 GUI「设置→记忆与进化→编辑」修改**，不能手改文件。

### 结论二：唯一可靠的触发方式 = 用户点名 / AI 自觉

- **用户点名**（最可靠）："过 delivery-audit""审查一下""按交付前审查规范检查"。
- **AI 自觉**：任务内容匹配 description 时主动加载。

### 结论三：本技能对 AI 的硬性自我要求 ★

**凡输出以下内容，一律自行附【交付审查】块，无需用户提醒：**
1. 任何结论、判断、建议、评估、测算；
2. 任何数值结果；
3. 任何事实性论断（法规/标准/文号/版本/参数）；
4. 任何文件/报告/代码/表格交付物；
5. 任何"完成/已修复/通过"的断言。

**形式**：正文末尾附【交付审查】块，四态标注（✅/⚠️SELF-ONLY/⚠️UNVERIFIED/❌）。
**用户看到这个块，即代表本技能已生效；没看到，即代表 AI 漏做，用户可一句话点破。**

### 结论四：诚实承认局限

本技能**无法从外部阻断 AI 的输出**。它只能：
- 提供方法（铁律+闸门+清单+脚本）；
- 通过【输出契约】把审查结果摊给用户看，**让用户能一眼识别 AI 是否跳过**。

**不要把"应该加载"当成"一定加载"。** 这是过去两个旧技能失败的根因。

### 结论五：自查的天花板（2026-10-17 实证）★

一个 779 行的计划文档，作者（AI）连续两轮"认真通读"后，仍漏掉 **8 处内部引用失效**和 **6 处结构矛盾**；
第三轮改用脚本机械扫描，5 分钟全部检出。

> **结论：靠"读"做一致性比对，错误率随篇幅线性上升；同一模型再怎么认真，也审不出自己盲区里的东西。**
> 这直接推出 L4 的落地要求：**必须换模型**，见 X 层。

## 0. 为什么需要它（读一次，记住立场）

历史教训：Skill 是按 `description` 匹配**按需加载**的，因此**"应该加载"≠"真的加载"**。
过去的防错技能（`conclusion-accuracy-gate`、`general-audit`）都写了"应该加载"，
但**从未真正被调用**——错误照犯。所以本技能的设计前提是：

- **不指望自觉，指望流程顺序**：审查动作在"宣称完成"**之前**执行。
- **不指望记忆，指望当场查证**：任何断言必须有本回合新取得的证据。
- **不指望肉眼，指望脚本**：能机械判定的，绝不靠读。
- **不指望自查，指望换模型**：同一模型的独立会话仍是同一双眼睛。
- **承认局限**：本技能无法从外部"阻断"输出。真正的保险是**输出契约**——
  把审查结果摊开给用户看，让用户一眼识别我是否跳过。

## 1. 六条铁律（L1~L6）

### L1 记忆非证据
训练记忆、上轮结论、类比推理、子代理口述——**一律不算证据**。
只认三类一手证据：
1. 本回合内**新跑**的命令输出；
2. 本回合内**Read**到的文件内容；
3. 本回合内**WebFetch/WebSearch** 到的原文（须给出 URL）。

> 说不清"它从哪来的"，它就是"我记的"——标记 UNVERIFIED，或去查。

### L2 存在 ≠ 准确
查到"有这个文件/字段/条款/函数"只完成 10%。必须再验：
- **准确性**：它到底写了什么？（数值/版本/条文原意）
- **适用性**：它适用于当前这个情形吗？
- **生效链路**：它真的被用上了吗？（存在于 schema 但运行时静默丢弃 = 假存在）

### L3 完成即怀疑
任何"完成 / 修复 / 通过 / 没问题"的断言之前，**默认假定它是错的，先证伪**：
1. 列出"如果这个结论是错的，最可能错在哪"（1~3 条）；
2. 指出"我最不确定的 3 个点"；
3. 找一个反例——什么情况会让它不成立？找不到才放行。

### L4 同源隔离 ★（v1.1.0 强化落地）
**校验路径必须独立于生成路径。** 不能用产生错误的同一记忆/同一查询/同一方法去验证自己。

**独立性的分级（关键）：**

| 做法 | 是否算独立 | 原因 |
|---|---|---|
| 同一会话再读一遍 | ❌ 不算 | 上下文已被自己污染 |
| 同一模型开新会话 | ❌ 不算 | 权重相同 → 盲区相同 |
| 同一厂商不同版本 | ⚠️ 弱独立 | 训练数据与对齐策略高度重叠 |
| **换厂商的另一个模型** | ✅ 算 | 数据分布、对齐方式、失败模式都不同 |
| 换人类专家 | ✅ 最强 | 有真实业务经验 |

- 数值：换工具/换语言/换公式独立复算；
- 事实：换一个独立信源交叉复核；
- **长文档一致性：必须换模型**——这是本技能 v1.1.0 的核心新增，见 §2.5。

### L5 校验优先
**先定义"什么证据能证明我错了"，再动手做/写。**
不是做完再补校验，而是做之前就想清楚验收标准。

### L6 能机判不人判 ★（v1.1.0 新增）
凡"存在/相等/包含/计数/指向"这类**无需理解语义**的判断，一律交给脚本，不交给模型。
模型只负责"语义是否合理""结论是否成立"。

> 反面教材：把"8 处引用是否失效"交给模型通读 779 行去发现——必然漏。
> 交给正则 + 标题抽取，5 分钟出结果且零漏。

## 2. 闸门体系：M 层 → 四段 → X 层

```
产出草案
   ↓
【M 层】机器自检（零判断，先跑，最便宜）
   ↓
【四段闸门】CLAIM → EVIDENCE → FRESH+INDEP → REDOUBT（判断，靠证据链）
   ↓
【X 层】换模型交叉验证（独立视角，最贵，最后做）
   ↓
输出 + 【交付审查】块（四态）
```

顺序不可颠倒：机器层先清掉"低级的、可机械判的"，避免浪费判断层和交叉验证的算力与注意力。

### 2.0 M 层：机器自检（6 类）

**先跑脚本，再读结果。** 脚本：`scripts/scan_doc.py`（当前支持 `.md` / `.txt`；`.docx`/`.xlsx` 先用提取脚本转纯文本再扫，脚本只做文本层检查，不解析格式）。

| 编号 | 检查类 | 判据 | 手段 |
|---|---|---|---|
| **M1** | 引用可达 | 所有内部引用（`§X.Y` / 第X章 / 附录X / 图X-Y / 表X-Y / "见上文"）指向的目标**存在**，且**语义对得上**（不能指向"排版"却落在"铁律"章） | 脚本出候选 → 人工确认语义 |
| **M2** | 计数自洽 | 同类计数全文一致（"N 条/N 项/N 类/N 处/N 人日"）；**合计 = 分项之和**；标题声称的数目 = 实际条目数 | 脚本 |
| **M3** | 契约同构 | 同一份 schema/结构在多处出现时，**字段集合完全相同**；每个字段有类型、有示例 | 脚本出差异 → 人工判定以哪份为准 |
| **M4** | 落盘对应 | 文中提到的文件/路径**实际存在**；目录树与正文**互补**（树上的每个条目正文有说明，正文提到的每个产物树上有位置） | 脚本 |
| **M5** | 枚举覆盖 | 正文声称"三档/四类/N 项"时，**枚举值确有 N 个**；同一概念只用**一种叫法** | 脚本 + 人工 |
| **M6** | 版本一致 | 表头/标题里的版本号与文档自身版本**一致**；只有"版本对照表"允许并列多个版本 | 脚本 |
| **M7** | 回归标记（防假修复） | 对照 `regression_markers.json`：每个 `checks[].scope` 节内，`must_contain` 必须全在、`must_not_contain` 必须全不在；`global_absent_except_changelog` 的错词全文（除 §0 变更记录）不得出现 | 脚本（`--markers`，缺省自动加载同目录 `regression_markers.json`） |

**M7 专治"假修复"**：作者写完变更日志写"已修 X"，实际 Edit 命中了**另一处**同名词、或根本没命中，正文还是错的——这类只靠读发现不了，靠"把修复落点钉死成可机检的标记"才兜得住。每个被声称修复过的位置，都应有一条 M7 标记。

**M 层不过，不进四段闸门。** 原因：连引用都指不到地方，讨论"结论是否成立"没有意义。

**M 层不是可选项。** 若因故未跑（如纯对话无文件），必须在输出契约里写明"未跑 + 原因"，不得留空。

### 2.1 ① CLAIM — 提取断言
列出本轮我做了哪些断言，分三类：
- **事实类**：M 是 N、A 等于 B、该文件/条款/标准存在且内容是 X
- **状态类**：已完成、已修复、已通过、测试全过
- **完成类**：可交付、无问题、符合要求

### 2.2 ② EVIDENCE — 绑定证据
给每条断言配上**一手证据**（命令+输出摘要 / 文件+行号 / URL）。
**无证据的断言 → 标记 UNVERIFIED，不许混入正文。**

### 2.3 ③ FRESH + INDEP — 新鲜且独立
- 证据必须是**本回合新取得**的，不能引用"上轮跑过""子代理说完成了"。
- **关键断言**（结论性、数值性、对外影响性）必须用**第二信源/第二种方法**交叉复核。

### 2.4 ④ REDOUBT — 反向怀疑
主动找反例："什么情况会让这个结论错？" 找不到反例才放行；找到则修正或限定范围。

### 2.5 X 层：换模型交叉验证 ★（v1.1.0 核心）

**为什么必须有这一层**：M 层查机械问题，四段闸门查证据链，但两者都跑在**同一个模型**上。
同一个模型的盲区是**重合的**——再认真，也看不见自己看不见的东西（见【必读】结论五）。

**AI 不能自己换模型，所以本层的设计是"产出工单 + 状态降级"：**

#### 触发条件（满足任一即必须做）
1. 交付物 > 300 行，或含跨章节引用/契约定义；
2. 输出的是**结论性判断**（评估、方案、计划、审查意见），且会影响后续决策；
3. 用户明确要求"认真审""交叉验证""换模型看看"；
4. 本次任务已出现过一次返工。

#### 动作（三步，缺一不可）
1. **生成盲审工单**：按 `references/cross-audit-template.md` 填一份自包含文件，落到
   `workdir/cross-audit-<date>.md`（无文件系统平台则直接贴出全文）。
   **工单里不得包含：自审结论、已发现的问题清单、"我认为没问题"之类暗示。** 否则污染对方判断。
2. **用户投递**：把工单交给**另一个厂商的模型**（优先级：不同厂商 > 同厂商不同版本 > 同模型新会话）。
3. **合并去重**：拿回结果后，与自审清单**按"问题位置+问题类型"合并去重**，冲突项以证据为准。

#### 状态后果（硬规则）
| 情况 | 最高可标状态 |
|---|---|
| 本机证据 + M 层（含 M7） + X 层完成 | ✅ VERIFIED |
| 本机证据 + M 层（含 M7），未做 X 层 | **⚠️ SELF-ONLY**（不得标 ✅） |
| 只有本机证据，M 层未跑 | ⚠️ SELF-ONLY，且须注明"M 层未跑" |
| 查不到证据 | ⚠️ UNVERIFIED |
| 被证据推翻 | ❌ REFUTED |

> **一句话**：没换模型，就没有 ✅。这不是不信任自己，是承认"同一双眼睛看不见自己的盲区"。

#### 🔴 红线：禁止"假修复式完成"声明（v1.1.2 新增，针对实证翻车）

**凡文档含 `regression_markers.json`（即有历史翻车点），以下规则强制：**

1. **写变更日志"已修复 / 改为 X"之前，必须先跑 M7 确认正文真的变了**——M7 不过，不许在变更日志里写"已修"。这是"假修复"（声称改了、实际没改）的正本清源。
2. **任何对外的"全修 / 完成 / 已修复"断言，必须 M7 绿 + X 层完成**，二者缺一：
   - 只能标 **⚠️ SELF-ONLY**，且正文/回复里**必须显式写明"未经独立模型复核，不得视为定稿"**；
   - **严禁**一边标 SELF-ONLY、一边嘴上说"全修完成 / 已闭环"——这两种表述互斥，同时出现即违规。
3. 若 X 层（换模型）在本环境无法执行（如用户未切换模型），**最高只能交付 SELF-ONLY 状态的交付物**，并把盲审工单留给用户去另一模型跑；不得自行填"已完成 ✅"。

> 实证：某计划文档 v0.11 的 §0.0 变更日志声称 17 项"已修"，独立 grep 证明其中 3 项是假修复（正文根本没改）。根因就是**没有 M7 这道机检，且作者以 SELF-ONLY 之身作出了"全修完成"的定稿式断言**。M7 + 上述红线就是要堵死这两点。

## 3. 红线词 STOP 表（出现即停，回到 ②）

以下表述一旦出现在我的草案里，**立即停止输出**，回到 EVIDENCE 重新取证：

| 红线词 | 问题 |
|---|---|
| 应该没问题 / 应该可以 | 未验证的乐观 |
| 我记得 / 印象中 / 一般来说 | 凭记忆代替查证 |
| 大概 / 可能 / 估计是 | 未取证的概率性断言 |
| 上次跑过 / 之前验证过 | 非本回合的新鲜证据 |
| 看起来正确 / 读起来没问题 / **通读了一遍** | 目测代替验证（长文档尤其致命） |
| 子代理说完成了 / 工具返回成功了 | 二手转述当一手证据 |
| linter 过了 / 编译过了就等于对了 | 局部通过 ≠ 整体正确 |
| **已审过 / 我核对过了**（未说明用什么手段） | 手段不明 = 未审 |

## 4. 输出契约（四态 + 降级保留）

任务收尾必须附一段**审查块**：

```
【交付审查】
M 层：M1-M7 ✅ / ⚠️ 未跑（原因：　）  ← 必须显式出现，不得省略；含 M7 回归标记（防假修复）
自审：✅ VERIFIED / ⚠️ SELF-ONLY / ⚠️ UNVERIFIED / ❌ REFUTED
X 层：已完成（对方模型：　，发现 N 处，合并后新增 M 处） / 未完成（工单：路径）
```

**四态定义**：

| 状态 | 含义 | 处理方式 |
|---|---|---|
| ✅ VERIFIED | 有本回合一手证据，经 M 层与**换模型交叉验证** | 正常写入正文 |
| ⚠️ SELF-ONLY | 自审通过，但**未换模型交叉验证** | 可写入正文，但**必须显式标注"未经独立模型复核"**，不得用于高风险决策 |
| ⚠️ UNVERIFIED | 查了但无独立信源 / 无法取证 | **保留但降级隔离**：单独成段、打 ⚠️、注明"未经核实，勿作决策依据"。**严禁混入正文冒充已核** |
| ❌ REFUTED | 证据推翻原结论 | 撤回，写明"原以为 X，实为 Y，出处 …" |

**核心原则**：允许"没查到"，允许"只自审"，**不允许"假装查到了"或"假装交叉验证了"**。
`⚠️ SELF-ONLY` 的存在，就是让用户能一眼区分"真审过"和"只是自己想了一遍"。

## 6. 执行序（写死顺序，不靠自觉）

```
干活
  ↓
M 层：跑 scripts/scan_doc.py（含 M7，自动加载同目录 regression_markers.json）→ 逐条看结果（不过则先改）
  ↓
① CLAIM → ② EVIDENCE → ③ FRESH+INDEP → ④ REDOUBT
  ↓
写变更日志"已修复/改为X"前：先确认 M7 绿（正文真改了，才允许写"已修"）
  ↓
X 层：生成盲审工单 → 用户投给另一模型 → 合并去重
  ↓
M7 绿 + X 层完成 → 可以输出"完成" + 标 ✅ VERIFIED
缺 X 层 → 只能说"自审通过"，标 ⚠️ SELF-ONLY，且显式写明"未经独立模型复核，不得视为定稿"
任一项未过 → 回去改；改不了 → 标 UNVERIFIED 并隔离
  ↓
绝不出现"先说完再补检查"；绝不出现"标 SELF-ONLY 却嘴上说全修完成"
```

## 7. 结构性变更后的强制回扫 ★（v1.1.0 新增）

以下操作**必然**造成引用/字段失效，做完必须立刻跑 M 层，不得跳过：

| 变更类型 | 必查 |
|---|---|
| 章节重排 / 新增章节 / 删除章节 | M1（所有 `§` 引用是否仍指向正确位置） |
| 文件改名 / 移动目录 | M4（正文提到的路径是否仍存在） |
| 字段改名 / 增删字段 | M3（所有出现该字段的地方是否同步） |
| 口径变更（"四类"改"五类"） | M2 + M5（所有计数与枚举是否同步） |
| 文档升版（v0.8 → v0.9） | **M6**（表头/标题是否还写着旧版本号） |
| **声称"已修复/改为 X"并写入变更日志** | **M7**（正文该处是否真改了；否则就是假修复，禁止写"已修"） |

> 实证教训：某计划文档 v0.6 取消一个模块导致章节重排，**8 处引用随即失效**，
> 而作者改的只是"新增那几段"，没人回头扫旧段落里的指针。这类问题只有脚本能兜住。

## 8. 关键原则（写在最后，也最要紧）

1. **先审后交**：没过闸门，不出现"完成/通过/没问题"。
2. **新鲜证据**：只认本回合跑出来的东西。
3. **能机判不人判**：存在/相等/计数/指向，交给脚本；语义合理性，才交给模型。
4. **换模型才算独立**：同一模型的任何形式复查，都只是"想了两遍"。
5. **敢说不确定**：`⚠️ SELF-ONLY` 与 `UNVERIFIED` 优于虚假的确定。
6. **承认架构局限**：本技能不能从外部阻断输出；靠流程顺序 + 输出契约自保。

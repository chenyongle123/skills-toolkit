# 交叉验证工单模板（换模型盲审）

> `delivery-audit` X 层的执行载体。用途：让**另一个厂商的模型**在没有先验污染的情况下，
> 独立审一遍同一份交付物，然后与自审清单合并去重。

---

## 使用规则（先读，三条硬规则）

1. **盲审**：工单里**不得**出现自审已发现的问题、不得出现"我认为没问题"、不得出现"请重点看第 3 章"。
   一旦暗示，对方只会去验证你的判断，再也发现不了你看不见的东西 —— 这一层就白做了。
2. **换厂商优先**：不同厂商 > 同厂商不同版本 > 同模型新会话。同模型新会话基本无效（盲区相同）。
3. **必须合并**：拿回结果后按"位置 + 问题类型"与自审清单合并去重，冲突项以证据为准。
   不做合并，等于白审。

---

## 工单正文（复制以下全部内容，替换 `【】` 后投给另一模型）

---

# 独立审查任务

你现在是一名严格的审查者。请对下面这份材料做**完整审查**，找出其中的问题。
这份材料由另一个 AI 生成，**没有任何人审过**。你的任务是找问题，不是评价优点。

## 一、材料

**类型**：【计划书 / 报告 / 合同 / 技术方案 / 代码 / 数据表 / 其他】
**用途**：【这份东西会被谁拿去做什么决策】
**篇幅**：【N 行 / N 字】
**材料全文**：

```
【在此粘贴完整原文，不要省略、不要只给摘要】
```

## 二、必须逐项检查的内容

### A. 结构一致性（机械可判，逐条查，不要跳）

| # | 检查项 | 具体要求 |
|---|---|---|
| A1 | **内部引用是否有效** | 所有"见第 X 章""§X.Y""见附录 X""如上表""图 X-Y"指向的目标**是否存在**，且**内容对得上**（不能指向"排版"却落在"铁律"章）。逐条列出失效的 |
| A2 | **计数是否自洽** | 同一概念在不同位置声称的数量是否一致（如一处说"四类"、另一处说"五类"）；声称的"合计"是否等于分项之和；标题声称的"N 项"与下面实际条目数是否相等 |
| A3 | **契约/结构是否同构** | 同一份数据结构的定义（schema、字段表、接口）在多处出现时，**字段集合是否完全相同**。列出只在一处出现的字段 |
| A4 | **声明与实物是否对应** | 文中提到的文件/路径/模块/函数**是否真的存在**；目录里列的东西正文是否有说明；正文提到的东西目录里有没有位置 |
| A5 | **枚举是否覆盖** | 声称"三档/四类/N 种"时，实际枚举值**是否真的有 N 个**；同一概念是否只用一种叫法 |

### B. 内容可靠（需要判断）

| # | 检查项 | 具体要求 |
|---|---|---|
| B1 | **无依据的断言** | 凡是"是/等于/存在/优于/必须"的论断，有没有给出出处或证据？把没出处的列出来 |
| B2 | **内部矛盾** | 同一件事在两处说法是否冲突（数值、范围、责任方、优先级、顺序） |
| B3 | **前提与边界** | 结论依赖的假设是否写明？假设不成立时结论是否还成立？有没有把特例当通例 |
| B4 | **遗漏** | 按材料自己声称的范围，有没有该写而没写的部分；声称"已处理"的是否真处理了 |

### C. 可用性（交给真人能不能执行）

| # | 检查项 | 具体要求 |
|---|---|---|
| C1 | **可执行性** | 每个动作是否有明确的输入、输出、责任人、判定标准？有没有"加强管理""注意质量"这类无法执行的话 |
| C2 | **验收可测** | 每条"验收标准"是否**能被机械或明确判定**？举出无法判定的 |
| C3 | **优先级与顺序** | 依赖关系是否成立（B 依赖 A，但 A 排在 B 后面）；优先级是否有冲突 |

### D. 【按材料类型补充】

- 计划类：工期是否低估、资源是否够、风险和任务是否对应
- 文档类：占位符残留、术语不统一、格式不一致、页码/目录错位
- 合同类：条款是否可执行、权利义务是否对等、有无遗漏的法定条款、引用法条是否现行有效
- 数据类：口径是否统一、量纲是否一致、合计算得对不对、异常值是否处理
- 代码类：边界条件、异常路径、资源释放、并发安全、依赖版本

## 三、输出格式（严格照此输出，便于与另一份清单合并）

先给汇总，再给逐条。

```
## 汇总
- 硬错误：N 处（会导致无法执行或结论错误）
- 中等问题：N 处（内部不一致、有歧义）
- 轻微问题：N 处（表述、格式）

## 逐条清单

| # | 位置 | 类型 | 问题描述 | 严重度 | 证据/依据 |
|---|---|---|---|---|---|
| 1 | L123 或 §3.2 | A1 引用失效 | "见 §7.3"，但全文无 §7.3 | 硬 | 标题清单中最大为 §7，无 §7.x |
| 2 | ... | | | | |

## 无法判断的项
- 项：… ／ 原因：材料未提供 …（不要猜，写"无法判断"）
```

## 四、禁止事项（违反即审查无效）

1. **不得只读开头结尾和摘要**。必须逐段读完全文。
2. **不得推测作者意图**后替作者圆场（"作者应该是想说…"）。只报"写了什么"和"这有问题"。
3. **不得因为文风专业、结构整齐就降低标准**。越整齐的文档越可能藏着系统性错误。
4. **不得修改原文**，只报告问题。
5. **不得省略**。发现问题必须写清位置（行号或章节号），便于核对。
6. **不得编造问题**。找不到就说"该项未发现问题"，不要为凑数硬找。
7. **不确定时必须明说**。写"疑似""无法判断 + 原因"，不要用模糊肯定句蒙过去。

## 五、特别提醒

这份材料最可能出错的地方，通常不是明显的错别字，而是：

- **改过结构但没改引用**（章节重排、文件改名、字段改名后，旧指针全部失效）
- **同一件事写了两遍，两遍不一样**（契约、字段、计数、流程）
- **声称做了但其实没做**（"已校验""已覆盖"却找不到对应机制）
- **验收标准写得像口号**（"符合要求""达到标准"却没说谁来判、怎么判）

请优先在这四类上花时间。

---

## 合并规则（拿回结果后执行）

1. 把对方清单与本方自审清单**并列**，按"位置 + 类型"对齐；
2. 同一问题两边都提到 → 合并为一条，标"双源确认"；
3. 只有一方提到 → 逐条核实证据，成立则采纳，不成立则记录反驳理由；
4. **对方提到而本方完全没看到的** → 标红，这是本方盲区，必须查清为什么漏；
5. 合并后的完整清单写入交付物附录，供用户复核。

# delivery-audit（交付前审查）

**把"看起来对"变成"经得起复核"。** 任何任务在输出最终交付物、给出结论/判断/数值、或声称"完成/通过/已修复"之前，加载本技能并执行审查闸门。**没跑完闸门，不许说"完成"；没换模型交叉验证，不许说"已核实"。**

## 触发条件（满足任一即触发）

① 生成/修改任何文件准备交付；② 输出含结论/判断/建议/评估/测算；③ 输出含事实性论断（法规/标准/文号/版本号/参数）；④ 输出含数值结果；⑤ 输出长文档（>300 行）或含内部交叉引用；⑥ 即将说出"完成/已修复/通过/没问题/我记得"等断言。

**不触发**：纯闲聊、单次文件读取、纯信息检索（无结论产出）。
**边界**：只做交付前审查，**不替代领域执行技能**；用户请求本身是领域任务（如编写投标文件、审核合同）时由对应领域技能执行，本技能在其产出交付物时触发，不因任务名称抢先加载。

## 核心机制

| 层 | 内容 |
|---|---|
| 六条铁律（L1–L6） | 记忆非证据 / 存在≠准确 / 完成即怀疑 / 同源隔离 / 校验优先 / 能机判不人判 |
| 四段闸门 | CLAIM → EVIDENCE → FRESH+INDEP → REDOUBT（每个声明都要过闸） |
| M 层机器自检（M1–M7） | 引用存在/计数一致/字段齐全/落盘可查/枚举合法/版本一致/**M7 回归标记（JSON 钉死"错词必须消失/对词必须出现"，防假修复）** |
| X 层交叉验证 | 换独立模型盲审（与生成方无共享上下文），工单模板见 `references/cross-audit-template.md` |
| 四态输出 | ✅ VERIFIED（已独立验证）/ ⚠️ SELF-ONLY（自审过，未换模型交叉验证）/ ⚠️ UNVERIFIED（查了但无独立信源，降级隔离）/ ❌ REFUTED（证据推翻原结论） |

## 输出

【交付审查】块——M 层结果（逐项 + 证据）+ 自审/X 层状态 + 诚实标注（未做的检查、已知限制）。

## 实测结论（2026-10-10，必读）

**不存在"自动强制"**——Skill 按 description 匹配、按需加载，没有任何设置/hook 能让它每任务必跑（写入 MEMORY/hook 强制三条路均已实测失败）。**唯一可靠触发 = 用户点名 / AI 自觉**。

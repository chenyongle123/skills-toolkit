# bid-tender-review ｜ 招标文件审查（投标方视角）

把任意招标文件（PDF / Word）中的**限制性条款**，规范、不漏、可追溯地提取为结构化核对清单。

> **核心边界：只提取与归类，不加工、不推演、不做决策。**
> 报价测算与投标决策权归投标人，本技能不越权。

---

## 一句话定位：把"厚"变薄，把"薄"审准

招标文件动辄几百页，投标人要的其实不是"读懂全文"，而是**从厚文件里捞出那几十条真正卡人的约束**——这就是"**把厚变薄**"。

但"变薄"本身不是目的。**薄下来的每一条，必须还能指回原文**（页码 / 条款号 / 原句），否则这份薄清单只是又一份需要复核的二手材料——这就是"**把薄审准**"。

本技能同时做这两件事：
- **提取层**：七类归集，把几百页压成一页清单 → 解决"看不见"
- **追溯层**：每条附出处与原文，可回原文核对 → 解决"不敢用"

> ⚠️ 边界重申：本技能负责**变薄 + 可追溯**，**不负责判断**。哪条是致命的、该不该投、报价怎么算，均由投标人基于清单自行决定。

---

## 它做什么

- 按**七类**归集限制性条款：① 时间节点与流程 ② 投标资格条件 ③ 废标/否决情形 ④ 评标与定标标准 ⑤ 履约保证金与商务条款 ⑥ 合同关键约束 ⑦ 形式与程序要求
- **保证金家族化分表**：投标 / 履约 / 质量 / 其他专项，逐类建表
- **通用↔专用逐条比对**：识别合同术语体系（条款 / 条件 / 短式 / 无通用专用之分），逐条取业主改写值
- **前附表 ↔ 正文交叉检索**：防"只看前附表漏全文"
- **暗标专项**：先判语境（本项目采用 / 仅否决条款引用），再决定是否展开 8 项
- 产出：七类清单 + **章节覆盖对照表** + 联系账户 + 待澄清清单 + 交付审查块 + 使用声明

## 它不做什么

- ❌ 不给出报价建议，不测算报价得分
- ❌ 不判断是否应当投标
- ❌ 不判断文件适用哪部法律、不下法域结论
- ❌ 不替投标人认定其已有 / 缺失某项证据
- ❌ 不评定风险等级，不输出"违法 / 无效 / 应当废标"等定性词

把 `bid-tender-review/` 整个目录放入你的技能目录即可（如 `~/.workbuddy/skills/`）：

```

├── SKILL.md                        # 主流程（11 条铁律 + 7 步处理 + 交付自检）
├── README.md                       # 本文件

    ├── 判词库.md                    # 通用扫描关键词（六类）
    ├── 清单模板.md                  # 七类清单字段定义与填写规范
```

## 设计原则

### 1. 只登记"类型规律"，不登记"个体内容"

判据：**换一个招标文件，这条还成立吗？**

| | 处置 |
|---|---|
| 成立（类型规律） | 写入，如"废标与否决为同一事项的两个名称" |
| 只是又一个例子 | 精简为**频率数字**，如"5 份中 2 份" |
| 不成立（个体内容） | **不写入**（具体项目名、容量、金额、章节号一律不进技能） |

原因：个体记忆是**判断**的温床——技能一旦记住上次某个文件长什么样，就必然拿记忆去比对，比对的产物就是判断，而且伪装成"提取"。

### 2. 一切命中数字均为"历史观察值，非阈值"

新样本超出历史区间**不构成异常**，不得据以判定"疑似漏扫"。数字的用途只有两个：说明各形态的**相对占比**，提示**术语选错时的数量级落差**。

### 3. 异名并扫

同一事项的多个名称必须并行扫描、合并归集：

- **履约保证金 ｜ 履约担保 ｜ 履约保函**（同一笔钱的三个名称）
- **废标 ｜ 否决**（同一后果的两个名称）

### 4. 交付自检（本技能自带）

收尾时按四段闸门自检，**不依赖、不强制调用任何外部技能**：

| 闸门 | 检查动作 |
|---|---|
| CLAIM | 逐条列出全部实质断言 |
| EVIDENCE | 每条给出一手证据（页/条款/行号＋原文），不得以记忆充当证据 |
| FRESH + INDEP | 关键数值须有独立来源复核，不得两处数字同源 |
| REDOUBT | 对"已完成/已覆盖/零命中"默认怀疑 |

> 注：`delivery-audit` 为其自身的独立技能，本技能对其为**弱引用**——环境中有则可在用户点名时配合使用，无则不影响本技能完整运行。本技能**不声称"强制执行外部审核"**。

## 使用方式

向 AI 提出以下任一需求即可触发：

- "审一下这份招标文件""看看有什么废标点"
- "提取评分项""分析投标资格条件"
- "给我一份投标核对清单""这份招标文件有什么要求"

支持上传 PDF / Word；也可指定关注点（废标项、评分点、资格条件、时间节点等）。

## 操作提示（实测经验）

**1. 文件太大就分段传。**
几百页的招标文件一次投喂，容易出现"前面读得细、后面读得粗"。按结构切块传效果更稳：

- 前附表 / 投标人须知 / 评标办法 → 一段
- 合同章（通用 + 专用）→ 一段
- 技术标准与格式要求 → 一段

**2. 一次处理一个文件，多份标书别混在一起。**
同一轮里同时处理多份文件，最容易发生**信息串档**——把 A 文件的保证金比例记到 B 文件的清单上。**一份文件跑完、清单确认无误，再开下一份。**

**3. 分段之后务必做一次"章节覆盖对照表"核对。**
分段传的代价是可能漏段。跑完用产出里的**章节覆盖对照表**（章节名 → 是否扫描 → 命中条款数）回头点一遍：文件有哪些章、哪章已提取、哪章未提取，**"未提取"的章要能说出理由**（如确无限制性条款），不能默认跳过。

**4. 关注点可以单独点名。**
不想跑全七类时，直接说关注点即可（"只看废标项""只提评分点"），技能会相应收窄，但**收窄后不改变"每条附出处"的要求**。

**5. 二次核对优先看"0 命中"项。**
清单里显示"本文件未载明"的项，是**最该回头确认的一格**——不是因为它可疑，而是因为"没找到"和"没有"在纸面上长得一模一样。

## 人工复核（必须保留的一环）

本技能产出**不是终稿**，是**供投标人复核的中间件**。以下三处必须人工过一遍：

- **待澄清清单**：文件载明值与法定基准不一致的条目，须向招标人澄清后再定
- **0 命中项**：写"未载明"的，建议回原文搜索确认
- **关键数值**：金额、比例、时限，逐条对回原句

> 技能的价值在于**把该看的地方指出来、把出处给全**，而不是**替人下结论**。
